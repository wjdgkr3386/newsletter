## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/src/Newsletter/Views/Admin/Recipients.cshtml
- **화면 이름**: 수신자 관리

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 화면 | 열기 | GET /api/recipients로 수신자 목록을 불러와 표시 |
| 수신자 추가 버튼 | 클릭 | 추가 팝업을 열고 GET /api/users?isRecipient=false로 목록을 불러온다. 검색칸·선택은 비운 상태로 시작 |
| 수신자 삭제 버튼 | 클릭 | 삭제 팝업을 열고 GET /api/recipients로 목록을 불러온다. 검색칸·선택은 비운 상태로 시작 |
| 검색칸 | 입력 | 입력할 때마다 바로 목록을 거르고 1페이지로 돌아간다. 걸러져 안 보이는 행의 선택은 그대로 유지한다 |
| 페이지 번호 (본문, 팝업) | 클릭 | 그 페이지의 10명을 보여준다. 팝업에서 고른 사람은 페이지를 넘겨도 선택이 유지된다 (D-077) |
| 행 | 클릭 (체크박스 또는 행 아무 곳) | 선택/해제. 선택 수와 실행 버튼 활성 상태를 바꾼다 |
| 전체 선택 체크박스 | 클릭 | 지금 보이는 행을 모두 선택/해제 |
| 실행 버튼 (추가) | 클릭 | 선택한 회원 id(다른 페이지에서 고른 사람 포함)로 POST /api/recipients 호출. 성공하면 팝업을 닫고 수신자 목록을 다시 불러오고 성공 알림. 본문은 지금 페이지를 유지하되 페이지 수가 줄면 마지막 페이지로 |
| 실행 버튼 (삭제) | 클릭 | 선택한 회원 id로 POST /api/recipients/delete 호출. 성공하면 팝업을 닫고 수신자 목록을 다시 불러오고 성공 알림 |
| 실행 버튼 | 실패 | 팝업을 닫지 않고 팝업 오류 알림에 message 표시. 팝업 목록을 다시 불러온다 (다른 관리자가 먼저 바꾼 경우 대비) |
| 취소 버튼, 닫기(X), 팝업 바깥 | 클릭 | 팝업을 닫는다. 아무것도 바뀌지 않는다 |

- 팝업에서 고르는 것 자체가 확인 단계이므로 삭제할 때 따로 확인 창은 띄우지 않는다.

## 5. 데이터

### 사용 API
| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | /api/recipients | 수신자 목록 (본문, 삭제 팝업) |
| GET | /api/users?isRecipient=false | 수신자가 아닌 회원 목록 (추가 팝업) |
| POST | /api/recipients | 선택한 회원들을 수신자로 추가 |
| POST | /api/recipients/delete | 선택한 수신자들을 삭제 |

### 사용 테이블
- recipients
- users
