# test.md

테스트 전략과 검증 기준을 정리한다. 작업을 "완료"로 표시하기 전에 아래 체크리스트를 통과시킨다.

---

## 1. 완료 체크리스트

작업이 끝날 때마다 위에서부터 순서대로 실행한다. 하나라도 실패하면 고친 뒤 처음부터 다시 실행한다. 같은 항목이 3번 연속 실패하면 loop.md "종료 조건"을 따른다.

### 코드 검토
coding_rule.md, database.md, security.md, api.md를 기준으로 코드를 읽고 확인한다.
1. 변수 타입 체크
2. 변수명 체크
3. 변수 사이즈 체크
   - DB와 연결되는 값은 database.md에 정의된 컬럼의 타입, 길이와 일치하는지 확인한다.
   - DB와 연결되지 않는 값도 변수 타입이 담을 수 있는 값의 범위와 실제로 들어올 값의 범위를 정확히 확인한다.
4. 메서드명 체크
5. 메서드 반환 타입 체크
6. 메서드 반환값 체크
7. 경로 체크
8. 파일 크기 체크: 수정하거나 새로 만든 파일이 700줄을 넘지 않는지 확인한다.
9. 보안 체크: security.md 규칙을 지켰는지 확인한다.
10. API 체크: api.md 정의와 경로, 요청, 응답, 오류 코드가 일치하는지 확인한다. API를 만들거나 수정하거나 호출하는 작업일 때만 확인한다.

### 빌드
11. 빌드(컴파일)가 오류 없이 성공하는지 확인한다.

### 테스트 코드
spec.md에 정의된 테스트 도구로 테스트 코드를 작성하고 실행한다.
12. 동등 분할 테스트: 입력값을 같은 결과가 나오는 구간으로 나누고, 구간마다 대표값을 하나 이상 테스트한다.
13. 경계값 분석 테스트: 각 구간의 경계값과 그 바로 앞뒤 값을 테스트한다.

### 화면 확인
화면 작업일 때만 실행한다.
14. 브라우저로 화면을 열어 해당 `{화면파일명}_screen.md`의 화면 요소, 동작, 상태별 화면대로 나오는지 확인한다.
15. 브라우저 콘솔에 오류가 없는지 확인한다.

### git 확인
git.md를 기준으로 확인한다.
16. `git status`로 이번 작업에서 만들거나 수정한 소스 파일과 문서가 모두 목록에 나오는지 확인한다. 목록에 없는 파일은 `git check-ignore -v {파일}`로 .gitignore에 걸렸는지 확인한다.
17. `git status`에 빌드 결과물(예: `bin/`, `obj/`)과 개인 설정(예: `.vs/`)이 나오지 않는지 확인한다.

## 2. 결과 보고

체크리스트를 마치면 사용자에게 아래 내용을 보고한다.
- 실행한 명령 (빌드, 테스트)
- 통과/실패 결과와 실패한 경우 원인
- 실행하지 못한 항목과 그 이유 (예: 브라우저 도구가 없음)
- 커밋할 파일 목록과 사용자가 직접 실행할 git add, git commit 명령 (AI는 커밋하지 않는다, git.md)
