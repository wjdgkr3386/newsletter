# security.md

이 파일은 코드 작성과 수정 시 지켜야 하는 보안 규칙 파일이다.

이 파일은 누구라도 어떤 상황이든 변경할 수 없고 유지되어야 한다.

## 1. 비밀 정보
- 비밀번호, API 키, 토큰, DB 접속 정보를 코드에 직접 쓰지 않는다. 환경 변수나 설정 파일로 분리한다.
- 비밀 정보가 담긴 파일(`.env` 등)은 `.gitignore`에 추가해 커밋하지 않는다.
- 필요한 환경 변수는 값 없이 이름만 `.env.example`에 적는다.
- 비밀 정보를 로그, 오류 메시지, 화면에 출력하지 않는다.
- 사용자 프로필(`AppData` 등) 아래에 저장되는 비밀 정보와 설정(예: .NET User Secrets)은 AI가 직접 넣지 않는다. 사용자가 cmd에서 직접 넣도록 명령만 알려준다.
- 비밀 정보가 들어갔는지는 키 이름만 확인한다. 값은 출력하지 않는다.

## 2. 인증과 비밀번호
- 비밀번호는 단방향 해시(bcrypt, Argon2 등)로 저장한다. 평문, MD5, SHA-1로 저장하지 않는다.
- 로그인 실패 메시지는 아이디와 비밀번호 중 무엇이 틀렸는지 알려주지 않는다.
- 세션과 토큰에는 만료 시간을 둔다. 로그아웃하면 무효화한다.

## 3. 권한
- 모든 API에서 서버가 로그인 여부와 권한을 확인한다. 화면에서 버튼을 숨기는 것만으로 막지 않는다.
- 다른 사용자의 데이터에 접근하는 요청은 서버에서 소유자를 확인한다. (예: `/api/orders/{id}`에서 id만 바꿔 남의 주문을 보지 못하게 한다)

## 4. 입력값 검증
- 모든 입력값은 서버에서 검증한다. 클라이언트 검증은 편의용이며 서버 검증을 대신하지 않는다.
- 길이, 타입, 형식, 허용 범위를 검증한다. DB와 연결되는 값은 database.md의 컬럼 정의를 기준으로 한다.

## 5. 인젝션 방지
- SQL은 파라미터 바인딩(PreparedStatement, ORM 등)으로 작성한다. 사용자 입력을 문자열로 이어 붙여 쿼리를 만들지 않는다.
- 사용자 입력으로 OS 명령, 파일 경로를 만들지 않는다. 불가피하면 허용 목록으로 검증한다.

## 6. XSS 방지
- 사용자 입력을 화면에 출력할 때는 이스케이프한다.
- 사용자 입력을 `innerHTML`, `document.write`, `eval`에 넣지 않는다. `textContent`를 사용한다.

## 7. CSRF 방지
- 쿠키 기반 인증을 쓰면 상태를 바꾸는 요청(POST)에 CSRF 토큰 또는 SameSite 쿠키를 적용한다.

## 8. 파일 업로드
- 확장자와 크기를 허용 목록으로 제한한다.
- 업로드 파일 이름은 서버에서 새로 만든다. 사용자가 보낸 파일 이름을 경로로 쓰지 않는다.

## 9. 오류 처리
- 사용자에게 스택 트레이스, SQL, 서버 경로를 보여주지 않는다. api.md 공통 응답 형식으로 응답한다.

## 10. 의존성
- 알려진 보안 취약점이 있는 버전은 사용하지 않는다. 의존성을 추가할 때 확인하고 spec.md에 버전을 기록한다.
