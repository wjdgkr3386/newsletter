# overview.md

프로젝트 개요의 기준 문서다. 작업 계획과 완료 조건은 이 문서를 기준으로 정한다.

기능이나 범위를 바꾸는 작업에서는 이 문서도 함께 갱신한다. 사용자 승인 없이 기능과 범위를 바꾸지 않는다.

비어 있는 항목이 있으면 작업 계획 전에 사용자에게 질문해서 채운다.

---

## 1. 기본 정보

- **프로젝트 이름**: 뉴스레터
- **한 줄 소개**: 평일 정해진 시간에 석유 관련 데이터(국제유가, 가격정보 등)를 HTML 뉴스레터로 만들어 수신자로 등록된 회원에게 이메일로 보내는 웹 서비스
- **목적**: 정해진 석유 관련 데이터를 평일마다 자동으로 수집해 수신자에게 이메일로 전달한다

---

## 2. 사용자와 권한

| 사용자 | 설명 | 할 수 있는 일 |
|---|---|---|
| 비회원 | 로그인하지 않은 사용자 | 회원가입(아이디, 비밀번호, 이메일, 이름 / 이메일 인증 코드 입력 필수), 로그인 |
| 일반 사용자 | 가입한 회원 | 수신자 테이블에 있으면(관리자에게 구두로 신청) 등록된 이메일로 뉴스레터 수신, 뉴스레터 히스토리 페이지만 접근(수신자 여부와 관계없음) |
| 관리자 | 개발자가 DB에 직접 INSERT 문으로 만든 계정 | 모든 페이지 접근. 뉴스레터 생성/발송, 보낸 메일 확인, 수신자 관리, 뉴스레터 설정 관리. 수신자 테이블에 있으면 뉴스레터 수신 |

## 3. 핵심 기능

<!-- 우선순위가 높은 순서로 적는다. todo.md 백로그는 이 목록을 기준으로 만든다 -->
| 기능 | 설명 | 사용자 | 우선순위 |
|---|---|---|---|
| 회원가입 | 아이디, 비밀번호, 이메일, 이름. 아이디/이메일 중복 불가. 이메일 인증 코드(6자리 숫자, 10분 유효) 입력 필수 | 비회원 | 1 |
| 로그인 | 일반 사용자와 관리자 구분 | 비회원 | 2 |
| 수신자 관리 | 가입한 회원을 수신자 테이블에 추가하거나 삭제. 일반 사용자는 관리자에게 구두로 신청. 보내진 이메일은 이 페이지에 표시하지 않음 | 관리자 | 3 |
| 뉴스레터 설정 관리 | 자동 생성 시간과 자동 발송 시간을 분 단위로 설정. 기본값 생성 07:50, 발송 08:00. 생성 시간은 발송 시간보다 앞서야 함 | 관리자 | 4 |
| 공휴일 등록 | 매년 1월 1일에 공공데이터포털 특일정보 API로 그해 공휴일, 대체공휴일을 받아 DB에 등록. 앱 시작 시 그해 데이터가 없으면 등록 | 시스템 | 5 |
| 뉴스레터 직접 생성/발송 | 생성 버튼과 발송 버튼을 따로 두고 언제든 누를 수 있다. 최신 뉴스레터 10개 목록(발송 여부 표시)과 수신자 목록을 각각 표시한다. 생성: 미발송 뉴스레터가 있으면 갱신, 이미 발송됐으면 새로 생성. 발송: 목록에서 미발송 뉴스레터와 수신자를 각각 선택해 발송. 수신자를 선택하지 않으면 전체 수신자에게 발송 | 관리자 | 6 |
| 뉴스레터 자동 생성/발송 | 웹 앱 내 스케줄러가 KST 평일(한국 기준 주말, 공휴일, 대체공휴일 제외) 설정된 생성 시간에 외부 석유 데이터로 HTML 뉴스레터를 생성하고, 설정된 발송 시간에 미발송된 가장 최근 뉴스레터를 Gmail SMTP로 전체 수신자에게 발송. 관리자 확인 없음. 데이터를 받지 못하면 발송하지 않고 생성 여부와 발송 여부를 상태로 남긴다 | 시스템 | 7 |
| 보낸 메일 확인 | 최근 30개 뉴스레터 목록. 발송 일시, 성공/실패 여부, 누르면 보낸 본문 보기. 수신자 목록은 없음 | 관리자 | 8 |
| 뉴스레터 히스토리 | 발송된 뉴스레터 전체를 최근 순으로 30개씩 페이징해서 보기 | 일반 사용자, 관리자 | 9 |

- 발송은 일부 수신자에게만 보내져도 실패로 본다. 실패한 뉴스레터는 미발송으로 보아 다시 발송할 수 있고 히스토리에는 보이지 않는다. 보내진 이메일은 발송 페이지의 뉴스레터 목록에 표시한다.
- 데이터를 받지 못해 생성되지 않으면 발송 페이지 목록에 "생성 실패" 행으로 표시한다.

## 4. 범위

### 포함
- 회원가입(이메일 인증), 로그인
- 뉴스레터 히스토리
- 평일 설정 시간 뉴스레터 자동 생성/발송, 생성/발송 상태 표시
- 매년 1월 1일 공휴일 API 등록
- 관리자: 뉴스레터 직접 생성/발송, 보낸 메일 확인, 수신자 관리, 뉴스레터 설정 관리

### 제외
- 뉴스레터 만들기(편집) 페이지 (나중에 필요, 이번에는 만들지 않음)
- 보낸 메일의 수신자 목록
- 메일 안의 수신 거부 링크
- 화면에서 관리자 계정을 만들거나 지정하는 기능
- 일반 사용자의 직접 구독 신청/해지
- 비밀번호 찾기
- 내 정보 수정, 회원 탈퇴
- 모바일 대응
- 서버 배포 (로컬에서만 실행)

## 5. 화면 목록

| 화면 | 파일 경로 | 설명 | 접근 권한 |
|---|---|---|---|
| 로그인 | Views/Account/Login.cshtml | 아이디, 비밀번호로 로그인 | 비회원 |
| 회원가입 | Views/Account/Register.cshtml | 아이디, 비밀번호, 이메일, 이름 입력. 한 화면에서 인증 코드 발송 버튼과 코드 입력 | 비회원 |
| 히스토리 목록 | Views/History/Index.cshtml | 발송된 뉴스레터를 최근 순으로 30개씩 페이징 | 일반 사용자, 관리자 |
| 히스토리 본문 | Views/History/Detail.cshtml | 뉴스레터 본문 보기 | 일반 사용자, 관리자 |
| 뉴스레터 발송 | Views/Admin/Send.cshtml | 생성·발송 버튼, 최신 10개 목록(발송 여부, 생성 실패, 보내진 이메일), 수신자 목록 | 관리자 |
| 보낸 메일 확인 | Views/Admin/SentList.cshtml | 최근 30개 목록, 발송 일시, 성공/실패 | 관리자 |
| 보낸 메일 본문 | Views/Admin/SentDetail.cshtml | 보낸 본문 보기 | 관리자 |
| 수신자 관리 | Views/Admin/Recipients.cshtml | 가입 회원을 수신자로 추가/삭제 | 관리자 |
| 뉴스레터 설정 관리 | Views/Admin/Settings.cshtml | 생성·발송 시간 설정 | 관리자 |

- 네비게이션은 좌측에 표시한다. 관리자: 모든 화면 메뉴 + 로그아웃. 일반 사용자: 히스토리 + 로그아웃.

### 화면 흐름
- 비회원: 로그인 → 회원가입 → (가입 완료) → 로그인
- 일반 사용자: 로그인 → 히스토리 목록 → 히스토리 본문
- 관리자: 로그인 → 뉴스레터 발송 ↔ 보낸 메일 확인(→ 보낸 메일 본문) ↔ 수신자 관리 ↔ 뉴스레터 설정 관리 ↔ 히스토리

## 6. 용어

<!-- 코드, 문서, 화면 문구에서 같은 용어를 쓴다 -->
| 용어 | 뜻 | 코드에서 쓰는 이름 |
|---|---|---|
| 회원 | 가입한 계정(일반 사용자, 관리자) | User |
| 관리자 | 관리자 권한 회원 | Admin (Role) |
| 수신자 | 뉴스레터를 받는 회원 | Recipient |
| 뉴스레터 | 생성된 HTML 메일 한 건 | Newsletter |
| 생성 | 데이터를 받아 뉴스레터를 만들거나 갱신 | Generate |
| 발송 | 뉴스레터를 메일로 보냄 | Send |
| 발송 기록 | 수신자별 발송 성공/실패 기록 | SendLog |
| 뉴스레터 설정 | 생성·발송 시간 | NewsletterSetting |
| 공휴일 | 발송 제외일(공휴일, 대체공휴일) | Holiday |
| 인증 코드 | 가입 이메일 인증용 6자리 숫자 | VerificationCode |

## 7. 제약 사항

- **지원 브라우저**: 제약 없음
- **기타**: KST 기준 평일(한국 주말, 공휴일, 대체공휴일 제외)에 설정된 시간으로 자동 생성/발송. 석유 데이터 출처(API)는 미정이며, 정해질 때까지 뉴스레터 생성은 임시 데이터로 만든다
