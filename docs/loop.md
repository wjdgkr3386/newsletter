# loop.md

이 파일은 누구라도 어떤 상황이든 변경할 수 없고 유지되어야 한다.

작업 하나를 진행하는 순서와 종료 조건을 정의한다. 모든 작업은 아래 순서를 따른다.

---

## 1. 작업 순서

세션을 시작하면 todo.md "진행 중"과 사용자의 첫 메시지에 따라 아래와 같이 시작한다.

| "진행 중" | 사용자의 첫 메시지 | 행동 |
|---|---|---|
| 작업 있음 | 작업을 지정하지 않음 (예: "이어서 해") | "계획 승인"이 승인 완료이면 사용자에게 이어서 할 작업과 "현재 단계"를 알리고 그 단계부터 진행한다. 승인 전이면 2번(승인)부터 진행한다 |
| 작업 있음 | 다른 작업을 요청함 | 진행 중인 작업을 멈추고 새 작업을 할지 사용자에게 묻는다. 새 작업을 하기로 하면 진행 중인 작업을 "계획 승인", "현재 단계"와 함께 백로그 맨 위로 옮긴다 |
| 비어 있음 | 구체적인 작업을 요청함 | 그 작업으로 1번(계획)을 진행한다 |
| 비어 있음 | 작업을 지정하지 않음, 백로그 있음 | 백로그 맨 위 작업으로 1번(계획)을 진행하고 2번(승인)에서 사용자 승인을 기다린다. 단, 그 작업에 "계획 승인"이 승인 완료로 남아 있으면 "진행 중"으로 옮기고 사용자에게 알린 뒤 "현재 단계"부터 이어서 진행한다. |
| 비어 있음 | 작업을 지정하지 않음, 백로그 없음 | 사용자에게 무슨 작업을 할지 묻는다 |

1. **계획**: todo.md "진행 중"에 목표, 완료 조건, 계획, 관련 파일을 적는다. overview.md 핵심 기능, 범위에 없는 작업이면 사용자에게 알리고, overview.md에 추가할지 확인한다.
2. **승인**: 계획을 사용자에게 보여주고 승인을 받는다. 결과는 todo.md "계획 승인"에 기록한다. 승인 전에는 코드를 수정하지 않는다.
3. **구현**: guide.md의 "읽는 시점"에 해당하는 문서를 읽고 따르며 구현한다. 화면 작업이면 아래 순서를 따른다.
   1. screen.md를 복사해 `{화면파일명}_screen.md`를 작성하고, 화면 시안 `docs/mockups/{화면파일명}.html`도 함께 만든다. 새 화면이면 overview.md "화면 목록"에도 추가한다.
   2. 사용자에게 `{화면파일명}_screen.md` 내용과 화면 시안(`docs/mockups/{화면파일명}.html`)을 보여주고 승인을 받는다. 결과는 "8. 사용자 확인 > 설계 승인"에 기록한다. 승인 전에는 화면을 만들지 않는다.
   3. 화면만 만든다. 기능은 만들지 않고, 필요한 데이터는 임시 데이터로 채운다.
   4. test.md 화면 확인(14~15번)을 실행한다.
   5. 사용자에게 화면을 보여주고 확인을 받는다. 결과는 `{화면파일명}_screen.md` "8. 사용자 확인 > 화면 확인"에 기록한다.
   6. 수정 요청이 있으면 반영하고 5번을 다시 한다.
   7. 확인을 받은 뒤 기능을 만든다.
4. **검증**: test.md 완료 체크리스트를 실행한다.
5. **수정**: 실패한 항목의 원인을 고치고 4번으로 돌아간다. 실패할 때마다 todo.md "재시도 기록"을 갱신한다.
6. **완료**: 완료 조건을 모두 만족하면 test.md "결과 보고"를 하고, todo.md에서 "완료"로 옮긴 뒤 "세션 인계"를 갱신한다. 완료 후 todo.md "백로그"에 작업이 있으면 맨 위 작업으로 1번(계획)을 진행하고 2번(승인)에서 사용자 승인을 기다린다. 단, 그 작업에 "계획 승인"이 승인 완료로 남아 있으면 "진행 중"으로 옮기고 사용자에게 알린 뒤 "현재 단계"부터 이어서 진행한다. 백로그가 비어 있으면 사용자에게 다음 작업을 묻는다.

각 단계를 시작할 때 todo.md "현재 단계"를 갱신한다.

## 2. 종료 조건

| 상황 | 행동 |
|---|---|
| 완료 조건을 모두 만족함 | 1번 순서의 6번(완료)을 진행한다 |
| 같은 체크리스트 항목이 3번 연속 실패함 | 작업을 멈추고, 작업은 todo.md "진행 중"에 그대로 둔다. "막힌 일"에 실패 항목, 시도한 방법, 오류 내용을 기록한 뒤 사용자에게 질문한다 |
| 목표나 완료 조건이 애매함 | CLAUDE.md 4번 규칙에 따라 사용자에게 질문한다 |
| 남은 컨텍스트가 부족함 | CLAUDE.md 2번 규칙을 따른다 |
